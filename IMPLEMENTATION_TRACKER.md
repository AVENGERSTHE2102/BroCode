# Waypoint implementation tracker

**Objective:** Deliver an action-first connected-data agent with fraud investigation, security triage, and codebase workflow packs over one graph/MCP/memory core; it reasons over sourced relationships, recommends or proposes bounded actions with explanations, verifies approved provider outcomes, and carries authorized memory into later sessions.

**Track priority:** Agents That Act on Connected Data is primary. Company Brain supplies evidence; Agent Memory and Coordination preserves facts, attempts, and handoffs.

**Constraints:** Cloud databases and services only. No Docker. Real integrations are required for acceptance. Synthetic data may be used for automated tests only. Never put credentials in this file.

## Decisions

- Use three workflow packs—fraud investigation, security triage, and codebase work—over one shared graph, MCP, authorization, memory, and audit core. Synthetic cases cover the three domains; live source adapters and model-driven tool selection are still required.
- Support GitHub repository actions and cloud deployment actions; actions require human approval bound to the exact target, inputs, and evidence revision.
- The user will deploy the Next.js app manually on their selected host; use Supabase Auth/Postgres for identity and control-plane storage, and FalkorDB Cloud for graph data. A host scheduler runs the Bun projection worker.
- Prefer a modular monolith and the smallest MCP tool surface that supports resolution, graph trace, memory, task coordination, action proposal, and explanation.
- No customer-data or production action acceptance until tenant isolation, credentials, authorization, audit, recovery, and verification gates pass.
